# MIFECO Dashboard Server & Architecture

The MIFECO dashboard ecosystem is served from `~/.hermes/pipeline-engine/dashboard/` via a Python HTTPS server with automatic HTTP→HTTPS redirect.

## Ports & URLs

| Port | Protocol | Purpose |
|------|----------|---------|
| **5540** | HTTP | 301 redirect → HTTPS on 5543 |
| **5543** | HTTPS | Dashboard content serving (self-signed cert) |

### Dashboard Pages

| Page | URL | Purpose |
|------|-----|---------|
| **Pipeline CC** | `https://192.168.1.77:5543/pipeline-dashboard.html` | Pipeline Operations Center with 5 pipelines |
| **Outreach** | `https://192.168.1.77:5543/outreach-dashboard.html` | Lead outreach, send/delete controls |
| **Hermes Agent** | `https://192.168.1.77:5543/hermes-dashboard.html` | Native Hermes dashboard launcher |

## Starting the Server

```bash
cd ~/.hermes/pipeline-engine/dashboard && python3 https-server.py
```

## Certificates

- Cert: `~/.hermes/ssl/server.crt`
- Key: `~/.hermes/ssl/server.key`
- Self-signed RSA 2048 with SAN: 192.168.1.77, 127.0.0.1, localhost
- Valid: 10 years
- Browser warning expected (click Advanced → Proceed)

## Server Code

The server script is at `~/.hermes/pipeline-engine/dashboard/https-server.py`. It runs two threads:
1. HTTP server on port 5540 (301 redirect to HTTPS)
2. HTTPS server on port 5543 (serves dashboard content)

## Shared Data Source: pipeline-state.json

All dashboards read from a **single shared JSON file** `pipeline-state.json` served alongside the HTML:

- **Location**: `~/.hermes/pipeline-engine/dashboard/pipeline-state.json`
- **Source of truth**: `~/.hermes/pipeline-engine/data/pipeline-state.json` (generated by `pipeline-sync.py`)
- **Sync mechanism**: `run-all-pipelines.sh` copies it from data/ → dashboard/ after each run
- **Dashboard loading**: Both Pipeline CC and Outreach fetch it on page load via `fetch('pipeline-state.json')` and overlay the counts onto static defaults
- **Cron**: Pipeline Ops Sync runs at 8:15 AM daily

## Unified Sidebar Navigation Convention

ALL dashboards must share the SAME navigation sidebar. When adding a new dashboard page or link, update ALL dashboards. The standard sidebar contains:

### Nav section (above separator):
- Books (#books), SaaS (#saas), Consulting (#consulting)
- Lead & Promotion (#lead-promotion), Pipeline Ops (#pipeline-ops), Pipeline Health (#pipeline-health)

### Nav section (below separator):
- Outreach Dashboard
- Hermes Agent

### Footer:
- MIFECO.com (target=_blank)
- Pipeline CC (cross-link to other pages)
- Back to Hub (index.html)

**Rule**: Never add a link to only one dashboard's sidebar -- it must appear in all dashboards that have navigation.

## Control Persistence via localStorage

Pipeline controls (Run/Pause/Stop state, threshold values) are persisted via `localStorage` under key `mifeco-pipeline-state`. Loaded via `loadPersistedState()` at page init, saved via `savePipelineState()` after every control change. Outreach sends/deletes use `outreach-sent` and `outreach-deleted` local-storage arrays.

## HTML Over SVG Pattern

Interactive dashboards (buttons, modals, scrollable lists, persistence) must be **HTML pages**, not SVG. SVG is suitable only for static diagrams and flow charts. The outreach dashboard was originally an SVG but was replaced with full HTML to support send/delete buttons, scrolling, and state persistence.

## Pipeline Flow SVG Pattern (8-Stage)

Each pipeline has a static SVG flow diagram in `flows/<pipeline-id>.svg`. These are 8-stage horizontal diagrams with the first stage highlighted. See `references/pipeline-flow-svg-and-tabbed-dashboard.md` for the exact template including positioning, colors per pipeline, and arrow connectors.

## Tabbed Kanban Dashboard Pattern

The `pipeline-dashboard.html` uses a tabbed layout with 5 pipeline panels. Each panel shows: pipeline header with health stats, SVG flow diagram, product/service cards, email/nurture info, an 8-column kanban board with lead cards, and quick stats. Data is loaded via fetch() from the JSON data files. See `references/pipeline-flow-svg-and-tabbed-dashboard.md` for the full HTML/JS architecture.

## Standalone Pipeline Kanban Board

The `kanban-dashboard.html` is a **focused kanban-only variant** — no pipeline headers, flow diagrams, product cards, or email sections. Just 5 tabs, each with an 8-column board. Data comes from `kanban-data.php` (tasks array with `pipeline` + `stage` fields). Features: inline card expand/collapse, assignee/priority/search filters, role-color-coded assignee badges, 30s auto-refresh. See `references/standalone-kanban-task-board.md` for the full architecture, data contract, stage definitions, and render pattern.

## 9 Pipeline Operations Center

Each pipeline card has:
- Run/Pause/Stop buttons (persisted)

- Stats: Total Items / Active / Queued
- Editable thresholds (monthlyTarget, qualifyRate, enrichRate)

## Dashboard Sync to Production (Cron: Daily 8:30 AM)

The dashboard sync deploys the local pipeline-engine dashboard to the live production server at `mifeco.com/admin/`.

### Correct Script Path

**⚠️ The cron prompt specifies `pipeline-engine/scripts/dashboard-sync.sh` but the actual absolute path is:**
```
/home/bob/.hermes/pipeline-engine/scripts/dashboard-sync.sh
```
Always run with the full absolute path:
```bash
bash /home/bob/.hermes/pipeline-engine/scripts/dashboard-sync.sh
```
Do NOT `cd` to a relative `pipeline-engine/` directory — it does not exist in the default working directory (`/home/bob/.hermes/hermes-agent/`). Searching for the script from scratch each session wastes time; use the absolute path directly.

### Sync Script Steps (what it does)

1. Copies all JSON data files from `data/` → `dashboard/` and verifies sizes
2. Warns if `content-command-center.html` is missing (non-blocking, expected)
3. Runs `rsync` incremental to `dh_mwpxuu@IAD1-SHARED-B8-42.DREAMHOST.COM:/home/dh_mwpxuu/mifeco.com/admin/`
4. Only changed files are transferred (typically `pipeline-dashboard.html` and `pipeline-state.json`)

### Webhook Refresh (POST-sync)

After sync completes, trigger the webhook to regenerate dashboards:

```bash
curl -sL -w "\n\n%{http_code}" -X POST https://www.mifeco.com/admin/webhook.php \
  -H "Content-Type: application/json" \
  -d '{"secret":"Rm2214ri%%%%","action":"refresh"}'
```

**Expected response:**
```json
{"status":"ok","action":"refresh","dashboards_regenerated":1,"timestamp":"<ISO-8601 timestamp>"}
```
HTTP 200 = success. `dashboards_regenerated: 1` confirms the dashboard was rebuilt on the server.

### Failure Modes

- **`content-command-center.html not found` warning**: Expected, ignore.
- **rsync connection failure**: Check DreamHost SSH access / network. The script uses `sshpass` with key-based or password auth.
- **Webhook returns non-200**: The webhook.php may have been updated or the secret may have changed. Check the file on the server.
