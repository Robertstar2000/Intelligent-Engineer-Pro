## Key Decisions Made in This Report Format

1. **Overview first** — executives want the headline numbers before details
2. **Per-pipeline tables with days-in-stage** — the most actionable metric
3. **Blocker summary as a separate section** — makes it scannable for CEO agent
4. **Email queue with ON HOLD flags** — prevents sending when nurture is broken
5. **Registry integrity as a PASS/FAIL** — binary signal for downstream systems
6. **Recommended actions prioritized by emoji severity** — 🔴 urgent, ⚠️ watch, 📈 opportunity

## Data Sources for Each Section

| Section | Source |
|---------|--------|
| Overview counts | `len(pipeline['pipeline']['leads'])` for each pipeline |
| Pipeline value | `sum(lead.get('value', 0) or lead.get('value_estimate', 0))` |
| Days-in-stage | `datetime.now(utc) - entered_stage` (ISO) or `created_date` (date-only) |
| Blockers | Books: stage 3 or 5 >7d; Consulting: any stage >7d; SaaS: stage 1 ≥7d |
| Nurture health | Compare ALL product titles in pipeline JSON against nurture sequence content |
| Registry integrity | Compare `registry['total_leads_all']` vs sum of actual leads |
